# SINYA 二手 PC 定價 — 9.0

二手 PC 回收、定價、標價、售出與經營分析工具（純前端，部署於 GitHub Pages）。
要多門市共用、帳號權限與正式稽核，請見 [整合規格](docs/INTEGRATION_SPEC.md)。

## 五個分頁

| 分頁 | 給誰 | 做什麼 |
|---|---|---|
| 查價作業 | 店員 | 新增回收品（即時試算建議售價）、篩選、排序、標價、售出、批次操作、匯出標價清單 |
| 經營總覽 | 主管 | 在庫與售出指標、庫齡分布、分類統計、滯銷清單、依實際成交的校正建議 |
| 回收估價 | 收購人員 | 依二手行情或新品價 × 殘值係數，算出建議收購價與「放到 180 天仍不虧」的最高收價 |
| 定價政策 | 主管 | 主管 PIN、所有定價參數（先看影響預覽再套用）、修改紀錄 |
| 資料管理 | 主管 | Excel／CSV 匯入匯出、範本、完整備份與還原 |

## 售價怎麼算

```
有參考市價（市價錨定）：
  錨定價 = 參考市價 × 品況係數 × (1 + 門市加成 5%)
  品況係數 = 成色（A 1.00／B 0.93／C 0.85／D 0.75）× 有維修 0.95 × 電池 <80% 0.95 × 配件不齊 0.97
沒有參考市價（暫用，列入待補）：
  錨定價 = 成本 ÷ (1 − 目標毛利率)
→ 庫齡折扣：30 天 -5%、60 天 -10%、90 天 -15%、180 天 -25%（可設分類專用階梯）
→ 成本底線：未滿 90 天毛利率 ≥ 10%；≥90 天最低到成本；≥180 天最低到成本 8 成
   （市價錨定時若底線高於錨定價＝收購成本偏高，依市價定價並標示）
→ 取整、尾數 9 往下取（都不破底線）→ 市價錨定時不高於錨定價
```

- **毛利率一律是財會口徑：毛利 ÷ 售價。** v8 的「毛利率」其實是加價率，升級時已自動換算（加價 20% → 毛利率 16.7%，售價不變）。
- **參考市價**＝同型號 A 級良品的二手行情，要填查價日期與來源；超過 30 天列入待補。
- **月係數**改名為「殘值係數」（相對新品價），只用在回收估價，不影響售價。
- 所有數字都可在「定價政策」調整；套用前會顯示影響幾件、合計差多少。

## 標價與售出

- **標價**：把建議售價寫成目前標價，留下標價紀錄。建議價與標價差距 ≥ 3% 或未標價，列入「需重新標價」。
- **售出**：填售出日與成交價，系統保留售出當下的建議價、錨定價、標價與庫齡，供校正分析。
- **低於成本**的標價或售出、刪除、取代匯入、還原備份、清空，需要主管 PIN。

## 資料欄位

庫存編號（自動產生、不可重複）、序號、名稱、分類、CPU／GPU／記憶體／儲存、成色、電池健康度、剩餘保固、配件齊全、維修、購買日、回收日、新品價、成本、目標毛利率、參考市價／日期／來源、單品加成、狀態、售出日、成交價、標價、標價日。

## 匯入

- 依第一列標題辨識欄位，順序不拘；v8 匯出的檔案也能匯入（毛利率自動換算）。
- 預設「依庫存編號更新，其餘新增」：重複匯入同一份檔案不會變兩份（沒有編號時，以序號或「名稱＋回收日＋成本」比對）。
- 百分比可填 `20%`、`0.2` 或 `20`；日期可填 `2025-08-04`、`2025/8/4`、民國 `114/8/4`、`20250804` 或 Excel 日期。

## 資料保存與限制

- 資料存在**這台電腦的這個瀏覽器**。換電腦、清除瀏覽資料前，請先「下載完整備份」。
- 主管 PIN 只能防止誤改，**不是資安防護**。
- 從 v8 升級時，舊資料仍保留在瀏覽器中，可在「資料管理」下載原始檔。

## 開發

```bash
npm ci
npm test            # 單元測試：定價引擎、資料模型、匯入匯出、經營分析
npm run test:e2e    # 瀏覽器煙霧測試（Playwright）
python3 -m http.server 4173   # 本機預覽：http://localhost:4173
```

- 程式為 ES Module，需經由 http(s) 開啟（直接雙擊 `index.html` 不能執行）。
- 每次推送 GitHub 都會自動跑測試（`.github/workflows/test.yml`）。

| `js/analytics.js` | 經營分析 |

| `docs/INTEGRATION_SPEC.md` | 併入二手平台後台的規格 |
